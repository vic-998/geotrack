做地图、车队、出行或者物联网，GPS 轨迹看上去就是一串经纬度。真正接起来，麻烦通常不在画线，而在画线之前。

一、轨迹看起来简单，做起来并不简单

只画一条线时，几行代码就够了。要做轨迹回放，点太多；要算里程，噪声会把误差放大；要做两条路线的比较，格式和坐标还得先统一。

不同设备带来的数据也不一样。有的是 KML，有的是 GPX，有的是坐标串，还有地图服务自己的压缩 polyline。每个项目都重新写一遍，代码很快就会散在各个角落。

这些问题不算难，麻烦的是总要重复做。

先把轨迹数据整理干净，后面的地图和业务才有意义。

二、GeoTrack 把这些基础活集中起来

GeoTrack 是一个轻量级 Java 21 工具库，没有 Spring，也没有数据库。它先把轨迹数据读进来，再按需要做转换、平滑、抽稀和分析。

先把数据读进来。支持 KML、GPX、逗号坐标串，也能处理 Encoded Polyline 和腾讯地图压缩 polyline。

再把坐标统一。提供 WGS84、GCJ02、BD09 之间的转换，批量处理整条轨迹。

然后处理噪声和点数。Kalman 负责在线滤波，RTS 负责离线平滑；Douglas-Peucker、Visvalingam-Whyatt 和 LTTB 用来抽稀和降采样。

最后做一点分析。轨迹相似度、Geohash、球面质心和停留点检测，都可以直接调用。

三、它不是地图 SDK，做的是前面那层工作

GeoTrack 不负责画地图，也不提供轨迹管理页面。它做的是地图和业务系统之间的那一层：把原始位置数据变成更适合计算、传输和存储的轨迹数据。

这样拆开以后，服务端可以用，批处理程序可以用，桌面工具也可以用。每个模块都是静态工具方法，没有隐藏状态，出了问题也比较容易定位。

如果你的项目已经有地图 SDK，GeoTrack 可以放在它前面，专门处理那些不适合塞进页面里的数据工作。

四、几段代码，把一条轨迹处理完

比如从 GPX 读取轨迹，再做坐标转换、RTS 平滑，最后压到最多 500 个点：

var raw = GpxTrackParser.parse("route.gpx");
var converted = CoordinateTransform.transformBatch(raw);
var smooth = KalmanTrackSmoother.smooth(converted);
var ready = TrackSimplifier.simplify(smooth, 500, 5D);

如果手里只有一段坐标串：

var points = PolylineParser.parse(
    "39.9000,116.4000,50,39.9100,116.4100,52");

还可以继续找停留点：

var stays = StayPointDetector.detectBySequence(points, 50D, 300D);

不用启动服务，也不用先搭一套框架。把依赖放进项目，传入轨迹点，就可以开始处理。

五、为什么把它开源出来

轨迹处理太常见了，所以更容易被重复实现。一份坐标转换代码放在服务 A，一份抽稀代码放在服务 B，另一个项目再复制一份解析器。

GeoTrack 先把这一层整理出来：接口小一点，依赖少一点，算法和测试跟着代码走。你可以直接用，也可以读源码、改参数，按自己的业务继续扩展。

六、从源码开始

环境要求是 JDK 21+ 和 Maven 3.9+。当前版本暂未发布到 Maven Central，可以直接从源码构建。

git clone https://github.com/vic-998/geotrack.git
cd geotrack
mvn clean package

写在最后

GeoTrack 做的事情不大：不替你画地图，也不替代完整 GIS 平台。

它只是把一条原始 GPS 轨迹，先处理成更稳定、更轻量、更适合分析的样子。

如果你正在做轨迹回放、里程计算、路线比较或停留识别，欢迎试试 GeoTrack。觉得有用，可以点个 Star；遇到问题，欢迎提 Issue。
